# 資料作成支援アプリ

会議メモ・議事録から次回会議に向けた資料の構成案を作成し、あらかじめ用意したコンサルスライドのデザインパターンから内容に合うものを自動選択して、PowerPoint（.pptx）として書き出すブラウザアプリです。

官公庁向け報告書・提案書のデザインを実物から再現しています。具体的には、経済産業省が公開しているNRI（野村総合研究所）作成の調査報告書PDF（2024FY/000700、2023FY/000283）から、配色・レイアウト・タイポグラフィをピクセル単位で抽出し、そのまま採用しました。

- **配色**: ネイビー `#000F78` を基調に、青を7段階（ネイビー→ミディアム→中間→ライト→ソフト→淡→極淡）用意しています。入れ子シェブロンや段階的に濃くなる帯のように同系色を並べて順序を表す図では、隣り合う段が識別できるだけの階調数が要るためです。区別はこの濃淡とグレーで付け、強調はビビッドブルー `#1A56DB`（「★推奨」マーカーを付けた1項目だけをハイライトする予約色）で表現し、オレンジは使いません。ピンク・レッドはさらに特別な強調点（リスク・警告など）だけに限定して使います
- **作法**: ベタ塗り＋白文字ではなく淡い塗り＋濃い文字を基本とし、番号は塗りつぶさず輪郭の丸で示します。罫線は細く、区切りは「→」の文字ではなく小さな三角形で表します
- **表**: 縦罫線を引かず、横だけを細い点線で区切ります。罫線でマス目を作らないことで視線が横方向に流れます。1列目（表側）は淡いブルーの見出し扱い、見出し行はネイビーのベタ塗りです。表を描くパターンはすべて共通の描画関数を通しているので、スタイルは1箇所で変更できます
- **フォント**: プレビュー・PowerPoint書き出しともに Yu Gothic UI に統一されています（`js/pptxExport.js` が全テキスト要素に自動で適用）
- **構成**: すべてのスライドが共通して「①ヘッダー（紺の縦棒＋パンくず形式の小見出し）→②メッセージ（結論を一文で言い切る太字ネイビーの見出し文＋任意のサブリード文の箇条書き＋細いヘアライン罫線）→③ボディ（メッセージの根拠となる図・表・チャート）→④フッター（出所表記・ページ番号）」という4層構成（結論ファーストの「ピラミッド原則」）で統一されています
- **本文**: ■（黒四角）の箇条書きマーカー、文中の重要な語句だけを太字＋ネイビーにする強調表現など、NRI報告書に特徴的な記法を再現しています
- **資料全体のストーリーライン**: 顧客に意思決定と次のアクションを促すことを目的に、「①背景・目的の説明 → ②論点を比較軸で整理（表・ボックス比較を積極活用） → ③推奨案の提案（★推奨マーカーで1案だけハイライト） → ④意思決定の確認 → ⑤アクションプラン（タスク・担当・期限）」という流れで構成案を組み立てるよう、Step 1のプロンプト生成（`js/promptBuilder.js`）が案内します。SCQA法・課題原因解決策・ピラミッド構造・PREP法など、定番のコンサル資料構成フレームに切り替えることもできます（下記「テーマ深掘り・ストーリー型選択」参照）

ビルド不要の素の HTML / CSS / JavaScript で作られているので、`index.html` を開くだけで動きます（PowerPoint出力ライブラリの [PptxGenJS](https://gitbrent.github.io/PptxGenJS/) はCDNではなく `js/vendor/` にローカル同梱しているため、社内の隔離ネットワーク環境でもそのまま動作します）。

色・タイポグラフィ・レイアウト寸法・コンポーネントの語彙・記法規約など、見た目に関する
ルールの詳細は [design.md](./design.md) にまとめています。新しいデザインパターンを
追加する際はあわせて参照してください。

## つかいかた

```
python3 -m http.server 8000
```

を実行して、ブラウザで `http://localhost:8000` を開いてください（`index.html` を直接ダブルクリックしても動作します）。

1. **Step 1（会議メモを入力）**: 会議メモ・議事録を貼り付けます。`#`/`##` の見出しや `-`/`・` の箇条書きがあると精度が上がりますが、フリーテキストでも解析します。「サンプルを試す」で動作イメージを確認できます。
   - **元ネタがまだ薄いとき**は「🔍 テーマ深掘り用プロンプトを作成」を押してください。テーマ・議題を入力し、「型1：論点整理を深めたいとき」「型2：提案書や企画書向け」「型3：抜け漏れを減らしたいとき」の3つから目的に合う型を選ぶと、テーマそのものを社内LLMに掘り下げてもらうためのプロンプトが生成されます。出力結果をこの下の入力欄に貼り付けてから、次のプロンプト作成に進んでください。
   - **構成案がうまくはまらないとき**は「🪄 社内LLM用プロンプトを作成」を押してください。このアプリの読み取りフォーマットに合わせて会議メモを整形するためのプロンプトが生成されます。モーダル内の「資料全体のストーリー型」で、意思決定型（デフォルト）・SCQA法・課題原因解決策型・ピラミッド構造型・PREP法から資料全体の論理構成を選べます（選ぶとプロンプトの該当部分がその場で切り替わります）。それを社内LLMのチャットに貼り付けて実行し、出力された構成案をコピーして入力欄に貼り付け直してから「次へ」を押すと、高い精度で構成案（リード文・サブリード文込み）に変換されます。
2. **Step 2（構成案を確認・編集）**: メモから自動生成したスライド構成（見出し・リード文・サブリード文・箇条書き）を確認し、自由に編集・追加・削除・並べ替えできます。リード文（メッセージ）はそのスライドの結論を一文で表すもので、空欄のままだと先頭の箇条書きが自動的に使われます。
3. **Step 3（デザインパターンを自動選択 → PowerPoint書き出し）**: 各スライドの内容（項目数・キーワード・数値の有無など）から最もふさわしいデザインパターンをルールベースで自動選択してプレビューします。Step 1のプロンプトを使った場合は、社内LLMが構成案の中で提案したパターン（🤖 AI選択）がそのまま使われます。プレビュー右上の**テンプレートを選ぶ**ボタンからギャラリーを開いて手動で選び直せます。プレビューの上部にある「項目数」コントロール（2〜5のクイックボタン＋－／＋のステッパー）で、ボックス比較・比較表などの項目数をその場で増減しながら見た目を確認できます。「PowerPointを書き出す」でPCに `.pptx` ファイルがダウンロードされます。

## テンプレート選択ギャラリー

Step 3の各スライドの「テンプレートを選ぶ」ボタンを押すと、全テンプレートを一覧から選べるギャラリーが開きます。

- **サムネイルは「そのスライドの実際の内容」で描画されます**。静的な見本画像ではなく、各テンプレートの描画処理をそのまま縮小表示しているため、「自分の原稿をこの型に入れたらどう見えるか」を並べて比較してから選べます（その記法では描けないテンプレートだけ、サンプル内容で表示されます）。
- **用途**（提案書／進捗MTG／報告書／キックオフ／経営・定例報告／構成図／汎用ロジック図解／データ提示／研修・説明会／会社・採用）と**役割**（目次／本文／比較／計画／KPI／表／図解）の2軸のチップで絞り込めます。例：「進捗MTG」×「計画」で5件に絞られます。
- テンプレート名・説明・カテゴリを対象にした検索ボックスもあります。
- **箇条書きの形が選んだテンプレートと合わなくても、プレビュー・書き出しが空になることはありません**。例えば「前提→検討→結論」（`前提：内容`のような1行完結のKV形式）用の箇条書きを、そのまま「ラベルボックス＋箇条書き（横並び）」（本来は「背景：」のような見出し専用行＋配下の複数行を想定）に手動で切り替えても、KV形式の各行を「ラベル＋1項目のグループ」として自動的に再解釈して表示します（小見出し＋箇条書き系の7テンプレート共通）。それでも表現できない組み合わせ（「---」区切りが必須の複合レイアウトなど）は、汎用の「タイトル＋メッセージ」表示に自動でフォールバックし、プレビュー上に「⚠ このパターンの形式に箇条書きが合わない」という注記が出ます。内容を編集するか、注記が出ないテンプレートを選び直してください。

### 項目数コントロール

ボックス比較・比較表・縦型比較のように「1行＝1項目」の箇条書きを使うテンプレートは、箇条書きの行数を直接編集しなくても、Step 3の各プレビュー上部にある「項目数」コントロールから素早く増減できます。

- **2／3／4／5のクイックボタン**：クリックした件数ちょうどになるよう、末尾を削るか、末尾に仮の項目（「項目N：説明を入力してください」）を追加します。
- **－／＋のステッパー**：1件ずつ増減したいとき、または6件以上に増やしたいときに使います。
- 追加された仮の項目はプレースホルダーです。Step 2の箇条書き欄で実際の内容に書き換えてください。
- このコントロールは箇条書きの行数を直接操作するので、「1行＝1項目」を前提としないテンプレート（ガントチャート・複合レイアウトなど）ではあまり意味のある結果になりません。その場合はStep 2で直接編集してください。

### 全レイアウトのサンプル書き出し（ブランドキット登録などに）

画面上部の「📦 全レイアウトをサンプル出力」ボタンを押すと、全78種類のデザインパターンをそれぞれ1枚のスライドにした一覧PowerPointファイルを書き出します（表紙込み79枚）。各スライドはテンプレートギャラリーのサムネイルと同じサンプルデータで描画され、見出しに「カテゴリ｜パターン名」、リード文にそのパターンの説明が入ります。PowerPoint Copilotのブランドキット登録用テンプレートを作りたい場合など、このアプリの全レイアウトをまとめて確認・共有したいときに使ってください（章ごとの色味アレンジはオフにしており、常に既定の配色で統一されます）。パターンを追加・変更したあとに再実行すれば、常に最新のレイアウト一覧を書き出せます（`DocAssist.exportSamplePptx()`）。

ギャラリーは `DocAssist.patterns` を直接読んでいるので、`js/patterns.js` にパターンを1つ追加すれば、サムネイル画像を別途用意しなくてもギャラリーに自動的に並びます（絞り込み用の用途・役割は `js/patterns.js` 末尾の `PATTERN_META` に1行足すだけです）。

## 自分で型（テンプレート）を追加する

「普段の業務で見かけたこの型を追加したい」というときに、**JavaScriptを書かずにテンプレートを増やせます**。ギャラリーの「＋ テンプレートを追加」から作成画面を開き、左側で設定すると右側のプレビューがその場で変わるので、見た目を確認しながら作れます。

作ったテンプレートはブラウザの `localStorage` に保存され、次回以降も組み込みパターンとまったく同じようにギャラリー・自動選択・PowerPoint書き出しから使えます。

### 設定できる項目

**カード型**（箇条書き1件＝1枚のカード）

| 項目 | 説明 |
|---|---|
| 並べる向き | 横に並べる／縦に並べる |
| 図形 | 四角／角丸／矢羽根（シェブロン） |
| 見出し帯 | つけるかどうか、どのデータを使うか、色 |
| 本文 | どのデータを使うか、塗りの色、■をつけるか |
| 装飾 | 連番、アイコン自動付与、矢印でつなぐ |

**表型**（箇条書き1件＝1行）

列を自由に増やせます。各列について「列見出し」「どのデータを使うか」「バッジ表示（状況／影響度）」「幅の比率」を指定します。

**データの指定**は、箇条書きのどの部分を使うかを選ぶ形です。`要件定義：山田｜完了｜9/10` という行に対して、

- 「見出し」→ `要件定義`
- 「内容」→ `山田｜完了｜9/10`
- 「内容の1番目（｜区切り）」→ `山田`
- 「内容の2番目」→ `完了`
- 「連番」→ `1`

**自動選択のキーワード**を設定すると、そのキーワードを含むスライドでこのテンプレートが自動的に選ばれるようになります。空欄にしておくと自動選択の候補にはならず、ギャラリーから手動で選ぶ専用のテンプレートになります。

### テンプレートの共有・バックアップ

ギャラリーの「書き出し」で、自作テンプレートをまとめたJSONファイル（`docassist-templates.json`）を保存できます。このファイルを同僚に渡して「読み込み」してもらえば、同じ型がそのまま使えます。同じIDのテンプレートは上書き、無いものは追加されます（組み込みパターンは上書きされません）。

書き出したJSONは人が読める素直な形なので、テキストエディタで直接編集してから読み込み直すこともできます。

```json
{
  "kind": "docassist-templates",
  "version": 1,
  "templates": [
    {
      "id": "custom-3-",
      "name": "3案の横並び比較",
      "category": "比較",
      "role": "比較",
      "scenes": ["提案書"],
      "keywords": ["比較", "検討", "案"],
      "minItems": 2,
      "maxItems": 6,
      "sample": ["A案：低コストだが拡張性に課題"],
      "layout": {
        "kind": "cards",
        "direction": "row",
        "shape": "rect",
        "icon": true,
        "connector": "none",
        "numbered": false,
        "head": { "show": true, "from": "key", "fill": "primary" },
        "body": { "from": "value", "fill": "light", "bullet": true }
      }
    }
  ]
}
```

## 🎨 テンプレートから配色・タイトルレイアウトを取り込む

自社の既存パワーポイントテンプレート（.pptxファイル）を読み込んで、その配色・フォント・箇条書き記号・タイトル枠のレイアウトをこのアプリに反映できます。画面上部のバーにある「🎨 テンプレートから取り込む」（適用後は「変更」）から、既存の.pptxファイルをアップロードしてください。

読み込んだ.pptxファイルの `ppt/theme/theme1.xml`（テーマカラー・フォント）、`ppt/slideMasters/slideMaster1.xml`（箇条書き記号・タイトルプレースホルダー）、`ppt/presentation.xml`（元のスライド寸法）を解析し、次の4点をこのアプリに反映します。

- **基調色**：テーマのアクセント1（無ければ濃色2）を取り込み、そこから既存の7段階の青系スケールと同じロジックで濃淡を機械的に生成します
- **フォント**：テーマの本文フォント（日本語指定があればそちらを優先）をプレビュー・PowerPoint書き出しの両方に反映します
- **箇条書き記号**：スライドマスターの箇条書き文字（`■` `●` など）を反映します。Wingdingsなどの記号専用フォントで指定されている場合は、文字化けを避けるため取り込みを行わず既定の `■` のままにします
- **タイトル枠のレイアウト**：スライドマスターのタイトルプレースホルダー（見出し文言の位置・サイズ・既定フォントサイズ）を読み取り、このアプリのヘッダー（パンくず＋結論見出し文）の位置とフォントサイズにそのまま反映します。取り込み元と書き出し先でスライド寸法が異なっていても、位置・サイズを比率に変換してから適用するため崩れません

**取り込まないもの**：タイトル以外のプレースホルダー（本文・画像など）の位置・サイズ、段組みは取り込みません。このアプリは「4層構造（ヘッダー／メッセージ／ボディ／フッター）」を土台に、色・フォント・箇条書き記号・タイトル位置だけを差し替える設計です。既存テンプレートの見た目を隅々まで複製するのではなく、社内で使われている配色・書体・タイトルレイアウトのトーンに寄せることを目的にしています。

**★推奨ハイライトは保護されます**：取り込んだテンプレートのアクセントカラーがオレンジや赤であっても、比較パターンの `★推奨` マーカーや警告表示の色は変わりません。これらは基調色とは独立した予約色として扱われるため、どのテンプレートを読み込んでも「本当に推奨する1項目だけをビビッドブルーで目立たせる」という意味づけが崩れないようになっています。

取り込んだ配色・レイアウトは端末の `localStorage` に保存され、次回アクセス時も引き継がれます。「既定に戻す」でいつでも既定の配色・レイアウト（紺系）に戻せます。

## スライドサイズ・フォントサイズ

- **スライドサイズ**：A4横向き（297mm×210mm、11.69インチ×8.27インチ）で書き出します。プレビューの縦横比もこれに合わせています。
- **最小フォントサイズ**：書き出したPowerPoint内のテキストは、原則として12pt以上になるよう自動的に底上げされます（`js/pptxExport.js` の `withDefaultFont` が全ての `addText`/`addTable` 呼び出しを横断してチェックする単一箇所での実装のため、新しいパターンを追加してもこの下限は自動的に効きます）。グラフ（棒グラフ・折れ線グラフ等）の軸ラベル・凡例など、PowerPointネイティブのグラフ機能が持つ内部フォントはこの対象外です。

## 🎲 出力時の自動アレンジ

同じデザインパターンばかりだと資料が単調に見えることがあります。そこで、**デザインパターン自体は一切変えず**、PowerPoint書き出しのタイミングだけで次の2点を自動的に少しアレンジします。

- **章ごとの色味の変化**：見出しの先頭パンくずセグメント（「｜」区切りの1つ目、例：「1. 背景・目的｜①課題認識」の「1. 背景・目的」）を章として扱い、章が変わるたびに基調色（`theme.primary`）の濃淡をわずかに変化させます。★推奨・警告用の予約色（`highlight`/`critical`/`pink`）、本文の黒・グレー、ボックスの塗り色（`light`/`lighter`/`pale`）には一切触れず、`js/pptxImport.js`のテンプレート取り込みと同じロジックで、1色から機械的にヘッダー・帯・チャート系統の色階調（`primaryLight`/`mid`/`accent`/`softBlue`）だけを再生成します。
- **見出しバー（キッカー）の装飾**：ヘッダー左端の縦棒を、四角・角丸・ドット付きの3パターンから資料ごとに1つ選びます（同じ資料内では統一されます）。

どちらも資料のタイトルや章構成から決まる**再現性のある値**（同じ内容なら常に同じ見た目）で、ランダムではありません。Step 3の「🎲 出力時に章ごとの色味・見出し装飾を少しアレンジする」のチェックを外せば無効化でき（元の単色・単一装飾に戻ります）、「🔄 アレンジ案を変える」を押すと同じ内容のまま別の組み合わせに切り替わります。プレビュー画面の見た目には影響せず、書き出したPowerPointファイルにのみ反映されます。

## スライドの構成（4層構造）

すべてのパターンで共通して、次の4層構造を使います（`js/pptxExport.js` が①②④を共通描画し、パターンごとの実装は③のみを担当します）。

1. **ヘッダー**: 紺の縦棒＋パンくず形式の小見出し。見出し文に `｜` を含めると複数セグメントのパンくず（例：「（１）調査の背景｜①課題認識」）として扱われる
2. **メッセージ**（リード文＋サブリード文）: そのスライドの結論・示唆を一文で言い切る太字ネイビーの見出し文と、任意のサブリード文。サブリード文はリード文を補足する短い説明を■マーカー付きの箇条書きで示し（1行＝1項目、複数行可）、本文の箇条書きと同じ地の文色で描画されます。直下に細いヘアライン罫線を1本引いてボディと区切る（色つきのボックスは使わない）。結論を先に示す「ピラミッド原則」に沿った構成
3. **ボディ**: メッセージの根拠を示す図・表・チャート。ここが各デザインパターン固有のレイアウト
4. **フッター**: 左下に出所表記（あれば）、右下にページ番号

Step 1のプロンプトが生成する `> リード文` / `>> サブリード文`（複数行可）の記法（`js/outline.js` が解析）を使うと、社内LLMに考えさせたメッセージをそのままこの構成に流し込めます。Step 2でも各スライドカードにリード文・サブリード文の入力欄があるので、手動での追記・修正も可能です。

### 本文（③）は必ず見出し・ラベルを添える

スライドいっぱいを無地の箇条書きで埋める場面は実務上ほとんど無いため、文章中心のパターン（タイトル＋メッセージ・2列箇条書き）でも、本文の各行に必ず何らかの見出し・ラベルを添えます。「ラベル：本文」の形式で書いた行はラベルをそのまま太字見出しにし、ラベルの無い行（コロンが無いただの文章）には丸囲み数字（①②③…）を自動で振ります。ユーザーが特別な記法を意識しなくても、書いたメモが自然に見出し付きの構成になります。

### 出所表記

箇条書きの中に `出所：◯◯`／`出典：◯◯` という行を書くと、その行は箇条書きから取り除かれ、スライド左下に出所表記として自動的に表示されます（Step 1のプロンプトにもこの記法の案内が含まれています）。

### 文中の強調（太字＋ネイビー）

箇条書きやメッセージの中で `**強調したい語句**` のように書くと、その部分だけ太字＋ネイビー色で表示されます（NRI報告書に見られる「重要な語句だけ目立たせる」表現の再現です）。色つきの背景（ネイビーの帯など）の上ではネイビー化はせず太字のみになるため、白文字が見えなくなることはありません。

### 推奨案のハイライト（★推奨マーカー）

比較系パターン（ボックス比較・縦型比較・比較表）で、箇条書きの項目の先頭に `★` または `★推奨` と書くと、その項目だけがビビッドブルーでハイライトされます（マーカー自体は表示前に取り除かれます）。例：`B社CRM：★推奨 コストと機能のバランスが良い`。オレンジは使わず、この予約色は1スライドにつき本当に推奨する1項目だけに使うことを想定しています。

## 用意されているデザインパターン（78種類・9カテゴリ）

`js/patterns.js` で定義しています。自動選択は内容に最も合うものを選びますが、迷ったときの代替候補として、テンプレートギャラリーから他のパターンにいつでも切り替えられます。

複合レイアウト（移行図・ガント・状況表など）は、区切り記号で列や要素を表す独自の記法を使います。

| 記号 | 意味 | 例 |
|---|---|---|
| `：` | 項目名と内容の区切り（全パターン共通） | `A案：低コストだが拡張性に課題` |
| `｜` | 列・段階の区切り | `要件定義：山田｜完了｜9/10` |
| `／` | 1つのグループ内の並列要素（移行図のゾーン内など） | `As-Is：基幹システム／顧客DB` |
| `（）` | 直前の要素の補足行（移行図のカード2行目） | `顧客DB（Oracle）` |
| `★` `★推奨` | 推奨・注目項目のハイライト | `B案：★推奨 バランスが良い` |
| 行末の `：`（内容なし） | 小見出し行（小見出し＋箇条書きパターン専用） | `背景：`（この行だけで独立させ、次の行から配下の箇条書きとして扱う） |
| 行頭の `-` | サブ項目（ノート風見出し＋箇条書き／前回の振り返り×本日の討議内容の左側専用） | `-サーバー保守費用`（直前の箇条書きの内訳として一段深くインデントされる） |
| `---` のみの行 | 2ブロックの区切り（前回の振り返り×本日の討議内容／棒グラフ＋示唆・課題／3×3優先度マトリクス＋配分ルール／アクション表＋決定事項で使用） | 箇条書きの中に3文字以上の `-` や `＝` だけの行を1つ入れると、それより前と後で2つのブロックに分かれる |

| アクションプラン | 課題・リスク一覧 | 課題・リスクを内容／影響度／対応方針の3列で一覧化する。`課題：内容｜影響度｜対応方針` の形式。影響度「高」だけがレッドで強調される |
| アクションプラン | 課題分類×内容→対応案（4列表） | 課題をカテゴリー別にグループ化し、「課題内容」から「対応案」への流れを矢印で示す4列の表。1行目に `列：カテゴリー｜課題｜課題内容｜対応案`、以降を `カテゴリー：課題｜内容1／内容2｜対応1／対応2` で書く。同じカテゴリーが連続する行は自動的に縦結合される |
| アクションプラン | ブロッカーと依頼 | 進行を止めている事象と、それを解消するための依頼を左右で対にして示す。`ブロッカー｜依頼内容` の形式 |
| アクションプラン | アクション表＋決定事項（2カラム） | 左に期日・担当・タスクの一覧表、右に番号付きの決定事項ボックスを並べる。箇条書きの中に `---` の区切り行を1つ入れると、前が左表、後が右の決定事項になる |

棒グラフ・折れ線グラフ・円グラフ・レーダーチャートはPptxGenJSの`addChart`機能を使ったPowerPoint本来のネイティブグラフとして生成されるため、書き出し後もPowerPoint上で数値やデザインを直接編集できます。

As-Is／To-Be移行図のアイコンも同様に、画像を貼り込むのではなくPowerPoint標準の図形（`flowChartDocument`、`flowChartMagneticDisk`、`cloud` など）で描いているため、書き出し後にPowerPoint上で色やサイズをそのまま編集できます。どのアイコンを使うかは要素名から自動で判定されます（「顧客DB」→円筒、「クラウド基盤」→雲、「帳票出力」→書類、など）。

## デザインパターンをコードで増やす（拡張方法）

上記の作成画面で作れる範囲を超えた複雑なレイアウト（As-Is／To-Be移行図やガントのような独自の描画）を足したい場合は、`js/patterns.js` に直接書きます。以下の形のオブジェクトを `DocAssist.patterns` 配列に追加するだけで、自動選択・ギャラリー・プレビュー・PowerPoint書き出しのすべてに反映されます。

```js
{
  id: 'kebab-case-id',        // 一意なID
  name: '表示名',
  category: '比較',           // 既存カテゴリ名と揃えると、同じ用途の兄弟候補としてまとまる
  description: '説明文（パターン一覧やギャラリーのツールチップに表示）',
  score(section) { ... },     // {heading, bullets} を見て 0〜10 程度で採点する関数
  renderBody(bullets) { ... },              // プレビュー用HTML文字列を返す（見出しは共通枠が描画）
  buildBody(pptxSlide, bullets, theme, box) { ... }, // PptxGenJSでスライド本文を組み立てる
}
```

あわせて、同ファイル末尾の `PATTERN_META` に絞り込み用の用途・役割を、`SAMPLES` にギャラリーのサムネイル用サンプルを1行ずつ追加します（`SAMPLES` は省略可。省略すると共通サンプルが使われます）。

```js
PATTERN_META['kebab-case-id'] = { scenes: ['提案書', '進捗MTG'], role: '比較' };
SAMPLES['kebab-case-id'] = ['項目A：説明', '項目B：説明'];
```

`js/analyze.js` にキーワード検出・数値検出・箇条書きのキー：バリュー分解などの共通ヘルパーがあるので、新しいパターンの `score()` 実装に利用できます。色は `js/theme.js` の1箇所で管理しているので、配色を変えたい場合もそこを直すだけです。同じ用途で見た目違いのバリエーションを増やしたい場合は、既存パターンと同じ `category` を指定するだけでプルダウンにまとまります（例：`フロー・プロセス`, `比較`, `マトリクス／ポジショニング`, `構造・ロジック`, `変化・対比`, `時系列`, `数値・グラフ`, `アクションプラン`, `汎用`）。

## 社内LLM環境との連携（コピー＆ペースト方式）

社内の隔離LLM環境はAPIから直接呼び出せないことが多いため、このアプリは**プロンプトをコピーして社内LLMのチャットに貼り付ける**方式で連携します。想定するワークフローは次の3段階です。

```
Step 0（任意）テーマを深掘りする  →  Step 1  構成案に整形する  →  Step 2-3  スライドデザインを決めて書き出す
  🔍 テーマ深掘り用プロンプト        🪄 社内LLM用プロンプト         このアプリ本体（既存のStep 2〜3）
```

### Step 0（任意）：テーマ深掘り用プロンプト

会議メモ・議事録そのものがまだ薄い、あるいは議論を深める前段階のときに使います。Step 1の「🔍 テーマ深掘り用プロンプトを作成」（`js/promptBuilder.js` の `DocAssist.buildDeepDivePrompt(theme, kind)`）でテーマ・議題を入力し、次の3つの型から選びます。

| 型 | こんなときに使う |
|---|---|
| 型1：論点整理を深めたいとき | 表面的な説明で終わらせず、現状／課題／選択肢／メリデメ／推奨方針まで実務判断レベルで掘り下げたい |
| 型2：提案書や企画書向け | 背景／現状課題／論点整理／選択肢比較／推奨案／実施ステップ／リスクまで、提案書にそのまま使える粒度で整理したい |
| 型3：抜け漏れを減らしたいとき | MECEを意識して、見落とされやすい論点・関係者ごとの利害・運用上のボトルネックまで洗い出したい |

出力結果は、そのままStep 1の入力欄（会議メモ欄）に貼り付けて次のプロンプト作成に進みます。

### Step 1：構成案整形プロンプト

Step 1の「🪄 社内LLM用プロンプトを作成」（`js/promptBuilder.js` の `DocAssist.buildOutlineFormatPrompt(rawNotes, storyType)`）を押すと、次の内容を含むプロンプトが生成されます。

- 入力した会議メモ本文（Step 0を使った場合はその出力）
- 官公庁向け報告書・提案書レベルの情報量・テキストヘビーな記述を求める指示
- 資料全体を選んだ**ストーリー型**で構成させる指示（モーダル内のプルダウンでその場で切り替えられます）

  | ストーリー型 | 主な目的・使いどころ |
  |---|---|
  | 意思決定型（デフォルト） | 「①背景・目的→②論点の比較整理→③推奨案の提案→④意思決定の確認→⑤アクションプラン」。提案書・企画書の初期提案など、資料全体で1つの意思決定に導きたいとき |
  | SCQA法 | S（状況）→C（複雑化）→Q（問い）→A（答え＝提案）。「なぜ今これに取り組むのか」を自分ごと化したい、キックオフや新規提案の初期合意形成向け |
  | 課題・原因・解決策型 | 課題（空）→原因（雨）→解決策（傘）。業務効率低下や売上低迷などのトラブルシューティング、改善プランの検討・合意形成向け |
  | ピラミッド構造型 | 結論（トップ）→根拠A・B・C（ボトム）。調査・分析結果の最終報告や、複数の選択肢から1つに決め切ってもらう意思決定の場面向け |
  | PREP法 | Point→Reason→Example→Point。急に意見を求められたときや、1トピックを手早く簡潔にまとめたいとき（スライド枚数は少なめ） |

- このアプリのパーサー（`js/outline.js`）が確実に読み取れる出力フォーマットの指定（`# タイトル` → `## 見出し` → `> リード文` → `>> サブリード文`（任意、複数行可） → `- 箇条書き` の構造、比較項目は「項目名：説明」で書くこと、推奨案には `★推奨` を付けること、アクションプランは「タスク｜担当｜期限」で書くこと、など）
- 利用可能なデザインパターン一覧（id・名前・説明）と、見出しの直後に `[pattern: パターンID]` の形式で最もふさわしいパターンを提案させる指示

このプロンプトを社内LLMで実行して得られた出力をStep 1の入力欄に貼り付け直すと、

1. きれいに構造化された構成案として読み込まれる（Step 2でも編集可能）
2. 見出しに含まれる `[pattern: xxx]` タグを `js/outline.js` が自動検出し、Step 3でそのパターンが「🤖 AI選択」として最初から適用される

という2つの効果が一度に得られます。タグが付いていない、または未知のIDの場合は自動的に無視され、通常どおりルールベースの自動選択（`js/patternSelector.js`）にフォールバックします。

社内LLMのプロンプト仕様に合わせて文言を調整したい場合は `js/promptBuilder.js` の1ファイルを直せば反映されます。パターン一覧は `DocAssist.patterns` から自動生成しているので、パターンを追加してもプロンプトの更新は不要です。ストーリー型・深掘り型を追加したい場合は、同ファイルの `STORY_TYPES` / `DEEP_DIVE_TYPES` に項目を足すだけで、Step 1のプルダウンに自動的に反映されます。

## 制限事項

- 構成案生成はルールベースのため、フリーテキストのままだと見出し・箇条書きの区切りが意図通りにならないことがあります。うまくいかない場合は「🪄 社内LLM用プロンプトを作成」を使うか、Step 2で自由に修正してください。
- アプリ自体はAPI通信を一切行わないため、会議メモの内容が外部に自動送信されることはありません。社内LLMへの連携は、ユーザーが手動でプロンプトをコピー＆ペーストする操作を介してのみ行われます。
- 自作テンプレートはブラウザの `localStorage` に保存されるため、**ブラウザやPCを変えると引き継がれません**。別の環境でも使いたい場合や、消える前に残しておきたい場合は「書き出し」でJSONファイルとして保存してください。
- 既存のPowerPointファイルから取り込めるのは配色・フォント・箇条書き記号のみです（「🎨 テンプレートから配色を取り込む」）。プレースホルダーの位置やレイアウトそのものを読み込んで自動的にテンプレート化する機能はありません。作成画面の設定項目（カード／表の組み合わせ）で表現できる範囲を超える型は、`js/patterns.js` にコードとして追加する必要があります。
- Webページのレイアウトを読み込んでテンプレート化する機能はありません。
