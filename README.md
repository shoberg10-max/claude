# 資料作成支援アプリ

会議メモ・議事録から次回会議に向けた資料の構成案を作成し、あらかじめ用意したコンサルスライドのデザインパターンから内容に合うものを自動選択して、PowerPoint（.pptx）として書き出すブラウザアプリです。

ビルド不要の素の HTML / CSS / JavaScript で作られているので、`index.html` を開くだけで動きます（PowerPoint出力ライブラリの [PptxGenJS](https://gitbrent.github.io/PptxGenJS/) はCDNではなく `js/vendor/` にローカル同梱しているため、社内の隔離ネットワーク環境でもそのまま動作します）。

## つかいかた

```
python3 -m http.server 8000
```

を実行して、ブラウザで `http://localhost:8000` を開いてください（`index.html` を直接ダブルクリックしても動作します）。

1. **Step 1（会議メモを入力）**: 会議メモ・議事録を貼り付けます。`#`/`##` の見出しや `-`/`・` の箇条書きがあると精度が上がりますが、フリーテキストでも解析します。**他のLLMで先に作成した構成案テキストをそのまま貼り付けても構いません**（見出し・箇条書き形式であればそのまま構成案として読み込みます）。「サンプルを試す」で動作イメージを確認できます。
2. **Step 2（構成案を確認・編集）**: メモから自動生成したスライド構成（見出し＋箇条書き）を確認し、自由に編集・追加・削除・並べ替えできます。
3. **Step 3（デザインパターンを自動選択 → PowerPoint書き出し）**: 各スライドの内容（項目数・キーワード・数値の有無など）から最もふさわしいデザインパターンをルールベースで自動選択してプレビューします。プレビュー右上のプルダウンから手動で変更することも、右上の「🤖 AIで一括判定」（または各カードの🤖ボタン）でLLMに判定させることもできます。「PowerPointを書き出す」でPCに `.pptx` ファイルがダウンロードされます。

## 用意されているデザインパターン（15種類）

`js/patterns.js` で定義しています。

| パターン | 使いどころ |
|---|---|
| タイトル＋メッセージ | キーメッセージ＋補足の箇条書き。汎用のフォールバック |
| アジェンダ／目次 | 本日お伝えする項目を番号付きリストで示す（表紙・目次向け） |
| ボックス比較 | 2〜4個の選択肢・案を横並びで比較 |
| SWOT分析 | 強み・弱み・機会・脅威の4象限で整理する |
| 2軸マトリクス | 4象限で分類・整理する |
| プロセス／フロー | 手順・ステップを順番に示す |
| サイクル図 | PDCAなど繰り返すプロセスを円環で示す |
| ファネル図 | 歩留まり・コンバージョンなど段階的に絞り込まれるデータを示す |
| ウォーターフォール | 数値の増減要因を積み上げ棒で示す（開始値→各要因→終了値） |
| ピラミッド構造 | 結論を頂点に、根拠（課題・原因・対策など）を土台に示す |
| ロジックツリー | テーマを複数の要素に分解して示す（MECE整理） |
| Before／After | 現状と施策後を対比させる |
| タイムライン／ロードマップ | 日付・フェーズを時系列に並べる |
| 比較表 | 5項目以上を表形式で一覧比較 |
| KPIサマリー | 数値・指標をカードで並べる |

## デザインパターンを増やす（拡張方法）

パターンの追加・変更は `js/patterns.js` の1ファイルで完結します。以下の形のオブジェクトを `DocAssist.patterns` 配列に追加するだけで、自動選択・手動切り替えプルダウン・プレビュー・PowerPoint書き出しのすべてに反映されます。

```js
{
  id: 'kebab-case-id',        // 一意なID
  name: '表示名',
  description: '説明文（パターン一覧やプレビューに表示）',
  score(section) { ... },     // {heading, bullets} を見て 0〜10 程度で採点する関数
  renderBody(bullets) { ... },              // プレビュー用HTML文字列を返す（見出しは共通枠が描画）
  buildBody(pptxSlide, bullets, theme, box) { ... }, // PptxGenJSでスライド本文を組み立てる
}
```

`js/analyze.js` にキーワード検出・数値検出・箇条書きのキー：バリュー分解などの共通ヘルパーがあるので、新しいパターンの `score()` 実装に利用できます。色は `js/theme.js` の1箇所で管理しているので、配色を変えたい場合もそこを直すだけです。

## 社内LLM環境への接続

### デザインパターンの自動選択をAIに任せる（実装済み）

Step 3の「⚙ AI設定」から、社内の隔離LLM環境などのAPIエンドポイントを登録できます。

- 対応形式: **OpenAI互換 Chat Completions**（Azure OpenAI・LiteLLM・vLLM等の社内ゲートウェイで広く使われている形式）／ **Anthropic互換 Messages API**
- 設定項目: リクエスト形式・エンドポイントURL・モデル名・APIキー（任意）
- 設定内容はブラウザの `localStorage` にのみ保存され、外部やこのアプリの開発元には一切送信されません
- 「🤖 AIで一括判定」（全スライド）または各プレビューカードの🤖ボタン（1枚のみ）でAI判定を実行できます。AI判定結果は「🤖 AI選択」バッジで表示され、失敗した場合はそのスライドだけルールベースの選択のまま残り、カード内にエラー内容が表示されます
- 手動でプルダウンから選んだ場合（✋ 手動選択）もAI判定結果と同様、Step 2に戻って内容を編集してもStep 3で上書きされません

社内LLMのAPI仕様がOpenAI互換／Anthropic互換のいずれとも異なる場合は、`js/llmPatternSelector.js` の `callOpenAiCompatible` / `callAnthropicCompatible` を参考に、新しい `format` を追加してください（プロンプト組み立てやレスポンスからのJSON抽出など共通処理はそのまま使えます）。

### 構成案の生成（現状はルールベース）

会議メモ→構成案の変換（`js/outline.js` の `DocAssist.outlineProvider(text)`）は、見出し・箇条書きの区切りを検出するルールベースの実装です。**別のLLM（社内チャットツール等）で先に構成案を作成してから、その結果をStep 1にそのまま貼り付ける運用を主に想定しています**（見出し・箇条書き形式のテキストであれば高い精度で読み取れます）。

この生成処理自体をアプリ内からLLM呼び出しに置き換えたい場合は、`DocAssist.outlineProvider` を差し替えてください。呼び出し側（`js/app.js`）はこの関数を呼ぶだけなので、内部実装をルールベースからLLM呼び出しに変更しても他のコードへの影響はありません（`js/llmPatternSelector.js` のOpenAI互換／Anthropic互換呼び出しをそのまま流用できます）。

## ファイル構成

```
index.html
css/style.css          全体のスタイル（プレビューのスライドデザインも含む）
js/app.js               画面遷移とUI（3ステップウィザード）
js/outline.js           会議メモ → 構成案（見出し＋箇条書き）のパーサー
js/analyze.js           キーワード検出・数値検出などの共通テキスト解析ヘルパー
js/patterns.js          デザインパターン定義（採点・プレビュー・PPTX生成）※拡張ポイント
js/patternSelector.js   構成案の各スライドに最適なパターンを選ぶロジック（ルールベース）
js/llmPatternSelector.js  パターン選択をLLM API（社内隔離環境等）に判定させるモジュール
js/pptxExport.js        構成案 → PowerPoint(.pptx) ファイルの書き出し
js/theme.js             プレビュー／PPTX共通の配色定義
js/vendor/pptxgen.bundle.js  PowerPoint生成ライブラリ PptxGenJS（MITライセンス、ローカル同梱）
```

## 制限事項

- 構成案生成はルールベースのため、複雑な文章では見出し・箇条書きの区切りが意図通りにならないことがあります。Step 2で自由に修正してください。
- 「⚙ AI設定」でLLMエンドポイントを設定していない状態では、アプリはブラウザ内で完結し、会議メモの内容が外部に送信されることはありません。エンドポイントを設定して「AIで判定」を使うと、そのスライドの見出し・箇条書きの内容が設定したエンドポイントに送信されます。
